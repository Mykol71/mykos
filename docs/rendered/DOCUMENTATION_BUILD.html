Build and verify the documentation

Documentation index

The public guide list in tools/docs/guides.json must match the viewer allowlist. Only those Markdown files are rendered; extra draft guides are excluded. The maintained sources are those guides, tools/docs/diagrams.json and tools/docs/theme.css. The graph model generates both Mermaid text and SVG using the same nodes/edges. SVG uses Graphviz for portable static layout; it is not a screenshot of a Mermaid renderer. Markdown renders with Marked GFM. Keep relative links for GitHub and Azure Repos; no browser Mermaid plugin is required.

Local build

Use Node.js 20+ and Python 3.9+. From the source root, install the exact direct build dependencies listed in tools/docs/package.json into that directory:

npm --prefix tools/docs ci --ignore-scripts
node tools/docs/build.mjs
python3 tools/docs/check.py
node tools/docs/build.mjs --check

These dependencies are documentation tooling, not installed server requirements. The exact direct versions and lock graph are included; update them deliberately and verify generated output when changing dependencies. The HTML and SVG are bundled so deployed hosts need neither Node nor npm. --check compares every generated file byte-for-byte without writing. check.py validates Markdown targets, rendered local links/anchors, diagram XML, viewer allowlists and protected-original hashes. Run viewer tests separately:

python3 -m pytest -q tests/test_supporting_docs.py

Never edit docs/rendered or generated .svg/.mmd files as primary sources. After a source edit, rebuild and include all changed generated files. Add a new guide or diagram to the explicit services/web/supporting_docs.py allowlist; do not broaden it to arbitrary filesystem paths. The fixed light stylesheet and documentation CSP are independent of the dashboard/system theme.
