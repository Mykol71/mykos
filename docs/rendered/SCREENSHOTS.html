The original container stays unchanged, and preview changes are discarded when the temporary session closes. Desktop VM previews can instead resume their saved RAM and disks.

Windows XP workflow

These examples use the actual MYKOS controls with an illustrative prepared XP image and instance. They show the UI workflow, not a newly tested Windows XP installation. Bring your own properly licensed Windows installation media and application software; see licensing.

1. Select the prepared XP image and an instance ID

Prepare and validate a winxp image using the image-build workflow, then open the Windows pane. Enter an eight-digit instance ID, select XP, and use the blue Start plus. Confirm the selected ID and image when prompted.

2. Open and manage the XP instance

Once startup completes, the row shows Up, its XP version, address, uptime and memory. Use HTTP graphical desktop to open the guest console. The row also provides Start, Stop, Snapshot and Delete controls. Stop retains the instance disks; Delete removes the instance and its saved data after confirmation.

The Windows XP desktop in the browser console

Opening HTTP graphical desktop brings up the guest’s actual graphical console. This capture shows the Windows XP desktop, including its Start menu button and taskbar. Guest OS activation and all vendor licensing requirements remain the operator’s responsibility.

Open the full-size Windows XP desktop.

3. Choose a saved recovery point

Use Snapshot container on the running instance to save a recovery point. In the Snapshots pane, select that instance's saved timestamp. Preview opens a separate temporary inspection session, Restore replaces the original instance's current state after confirmation, and Delete removes the selected snapshot. See Snapshot Preview for limits and cleanup behavior.

Ubuntu desktop workflow

Prepare a compatible Ubuntu desktop image using the image-build workflow. In the Ubuntu pane, choose the prepared version and enter an eight-digit instance ID, then use the blue Start plus and confirm the selection. When the instance reports Up, open HTTP graphical desktop and sign in with the guest account configured for that image.

The browser console opens the actual Ubuntu graphical desktop. This capture shows the desktop with its dock, Home and Trash icons. Each customer instance keeps its own accounts, configuration and data; the shared prepared image provides the starting OS environment.

Open the full-size Ubuntu desktop.

Use the instance row’s Stop and Start controls to retain and resume its disks, and Snapshot to capture a supported recovery point. See Snapshot Preview before choosing Preview or Restore.

Android-x86 desktop workflow

This example uses the legacy Android-x86 9.0-r2 VM (android9). The MYKOS control images use illustrative prepared-image and instance data. The setup and desktop images are actual captures from a running MYKOS-hosted Android guest. Android-x86 9.0-r2 is an older compatibility guest; use an isolated test environment and review the Android image-build guidance. All vendor and application licensing requirements apply.

1. Complete Android setup and prepare an image

Run sudo mykos, choose c. Build image, enter android9, and choose the required RAM. Follow the linked manual installer instructions and open the base image's HTTP graphical desktop. Complete Android's welcome wizard until the home screen with app icons appears. Guest setup is separate from signing in to MYKOS.

2. Select the prepared Android image and an instance ID

Open the Android-x86 pane, enter an eight-digit instance ID, select 9.0-r2, and use the blue Start plus. Confirm the selected ID and prepared image.

3. Open the Android desktop

When the instance reports Up, choose HTTP graphical desktop. Use the Android home screen and app launcher inside the browser console.

Open the full-size Android desktop.

4. Save and select a recovery point

Use Snapshot container on a supported running Android instance. In the Snapshots pane, choose its saved timestamp. Preview opens a temporary VM inspection session; Restore replaces that instance's saved state after confirmation; Delete removes the selected recovery point. Read Snapshot Preview for limitations and cleanup.

Debian native container workflow

This example uses Debian 13 (debian13) as a native Linux container. It shares the MYKOS host kernel and provides a shell-based environment. The screen examples use illustrative IDs, addresses, memory and recovery points.

1. Build and select Debian

Run sudo mykos, choose c. Build image, and enter debian13. Wait for the individual build to complete. Open the Debian pane, enter an eight-digit instance ID, choose 13, and use the blue Start plus. Confirm the selected ID and image. See native image builds.

Open the full-size Debian selection example.

2. Use the Debian shell and lifecycle controls

Once the instance reports Up, use su - root (admin only) to open its terminal. Commands such as cat /etc/os-release, id, and uname -r identify the guest userspace, current user and shared host kernel. Use the row's console log to inspect startup messages. Stop and Start manage a persistent instance; Delete removes its saved data after confirmation.

Open the full-size Debian instance example.

3. Select a Debian recovery point

Use Snapshot container on the supported running container. Select a saved recovery point in the Snapshots pane. Native Preview opens a separate, filesystem-only shell without guest networking; it does not resume the saved services or RAM. Restore replaces the original instance's state after confirmation. See Snapshot Preview.

Open the full-size Debian snapshot example.

The qualified native workflow uses the default UTC timezone and managed NAT. Custom-timezone snapshots and VPN creation for this family remain outside the qualified workflow; see image-build limitations.

SUSE Linux Enterprise native container workflow

This example uses SUSE Linux Enterprise BCI Init 15 SP7 (sles15sp7), the container base supported by MYKOS. A full SLES installation, desktop environment, subscription and paid vendor support are separate from this BCI container. Vendor licensing and any subscription requirements for additional software apply. The screen examples use illustrative instance data.

1. Build and select the SUSE BCI image

Run sudo mykos, choose c. Build image, and enter sles15sp7. After the individual image is ready, open the SUSE Linux Enterprise pane, enter an eight-digit instance ID, select 15 SP7 (BCI), and use the blue Start plus. Confirm the selected ID and image. See native image builds.

Open the full-size SUSE selection example.

2. Open the SUSE container terminal

When the row reports Up, use su - root (admin only). Inspect cat /etc/os-release and id to confirm the SLE BCI userspace and root shell. Native containers share the host kernel. The row also exposes console logs, Start, Stop, Snapshot and Delete controls for the managed instance.

Open the full-size SUSE instance example.

3. Choose a SUSE recovery action

Use Snapshot container, then choose the saved timestamp in the Snapshots pane. Preview provides a temporary filesystem-only shell without guest networking; Restore replaces the original instance's state after confirmation. Delete removes the selected recovery point. Read Snapshot Preview before choosing an action.

Open the full-size SUSE snapshot example.

Use the qualified UTC / managed-NAT native workflow. Custom-timezone snapshots and VPN creation for this family remain unqualified; follow the current image-build limitations.
