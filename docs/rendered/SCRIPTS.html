Documentation index

Use sudo mykos for the menu workflow on an installed host. Most legacy scripts are interactive and depend on their current working directory. The following paths are relative to /usr/local/share/mykos unless an absolute path is shown. Do not execute legacy administration scripts on a development desktop just to inspect their help. They often perform mutations immediately and have no dry-run mode.

All global installer actions accept --root DIR for isolated file staging. Mutating actions accept --dry-run; no external changes are performed by that flag. The old bundle utility does not have the global installer's staging-root mode.

Menus

MENU routes to back/MENU, pos/pos, repo/MENU, and data/MENU. Root is expected for operational use. MENU creates /backups if absent. .envtype in the toolkit root supplies its display name; create it manually as root when desired. Submenus return to the launcher directory so relative support paths resolve.

The repository menu advertises Create/Delete, but create_repos and delete_repos are absent. The data menu displays Pricing, Insights, and Dell TSR items without handlers. Only Summary/Detail are implemented there. These are existing product gaps, not hidden features supplied by the installer.

The legacy scripts have limited input validation and should be operated only by trusted host administrators. The account restriction is a legacy shell wrapper, not a general SSH sandbox. Review SSH restrictions and backup-user permissions for your environment. tfrsync.pl client software is external (ostools). A typical client backup command documented by the old project is:

tfrsync.pl --cloud --backup=all --rsync-account=tfrsync-01234567 --cloud-server=YOUR_HOST --force-rsync-account

This command runs on the client with its own prepared SSH keys and software, not inside the installer. Scheduler setup and a tested restore are separate operations.

POS containers (cd /usr/local/share/mykos/pos)

./pos is interactive: choose shopcode/image, build images, start/stop containers, connect as container root, and add/remove VPNs. It uses hidden files .shopcode, .SHOP.postype, .SHOP.imagetype, .SHOP.container, and .SHOP/ VPN data. Preserve those files during upgrades. Image creation uses livemedia-creator, kickstarts in ks/rh7.ks through ks/rh10.ks, Podman build/commit, and site repositories.

The legacy menu's default guest/image selection is RH8; this does not restore RHEL 8 host support. Its staging logic uses that global value; selecting another image does not comprehensively update all launch logic. Use the new configured API launcher for controlled, noninteractive staging, and validate legacy image workflows before relying on them across OS versions.

./get_peers reads Meraki configuration from /etc/mykos/pos.env and prints the organization's third-party VPN peers through jq. Configure credentials first. The legacy VPN update performs a PUT of a single constructed peers list; it can replace other configured organization peers. Review the intended full peer list and Meraki API behavior before using that menu option. Secrets are no longer embedded in maintained code, but legacy per-shop generated files may still contain them.

./pipework HOST_INTERFACE -i eth1 CONTAINER dhclient adds the container interface and obtains DHCP. It changes host/container networking and requires root and Linux network tooling. The new staging helper calls this exact form. Check interface, DHCP client availability, routes, and VPN policies in your staging environment.

The legacy Purge action stops all rootful Podman containers, prunes images, and removes hidden state. It is broad and destructive; it is not part of installation, update, removal, or the API's single-shop stop operation.

Do not expose helper sockets over TCP or make them world-writable. They are internal protocols; integrations should use authenticated HTTP API v2.

Repository mirrors (cd /usr/local/share/mykos/repo)

Script Behavior
./bin/list_repos Lists Apache-hosted repository URLs
./bin/repos_status Prints Apache active status
./bin/disable_repos Toggles the entire host Apache service, affecting more than mirrors if the host also proxies the dashboard
./bin/sync_repos Installs httpd/Podman as needed, enables Apache, creates privileged temporary UBI containers for RHEL 7–10, runs reposync/createrepo, removes containers

Synchronization needs working registry/network/subscription access and enough disk. Pinned historical UBI tags may need review. The script is not invoked or scheduled by the global installer. Review its failure handling and target repositories before running it against production mirrors.

Review report scripts before using them for billing decisions: the summary script can overwrite Daisy detection with Unknown, and success matching/counts have legacy assumptions. Reports use shared /tmp names. No guarantee of billing accuracy or secure publication is implied by copying these scripts. Email scripts must be reviewed for recipients, credentials, transport, and approvals before scheduling. The installer supplies support scripts at /usr/local/bin for compatibility but never executes them, publishes TSR content, or sends email.

Host utilities

bin/updateos [groupname|scriptname|help] [dry] is a legacy root script downloader and executor. It defaults to a historical HTTP backend, caches scripts under /usr/bin/.updateos, and uses MD5 comparison. Its dry behavior is specific to individual commands and may still perform downloads. It is not used by the new installer; audit and configure trusted delivery before operational use.

bin/blacklist.sh downloads IP lists and modifies iptables/ipset rules; it reads /etc/ip-blacklist.conf and related manual-blacklist state. bin/blacklist_login_attempts follows /var/log/secure and appends invalid-login source IPs to a manual blacklist. These are third-party/legacy tools, not enabled services. They can block legitimate administrators and conflict with firewalld policy; inspect them before enabling.
