MYKOS dashboard UI guide

Documentation index

Use this guide to find a feature, identify an icon, and understand what happens when you select a control. It describes the dashboard through the peer compact UI and peer-map updates (hotfix188). Controls depend on your role, host configuration, available images, and resource state. Hover over an icon for its action name; keyboard users can move between controls with Tab and activate buttons with Enter or Space.

Start here

Open /mykos/ on your MYKOS host and sign in with your browser account. The login page also offers theme, API, and Docs links. Browser accounts, API keys, backup SSH accounts, and guest OS credentials are separate identities.

A standard user can inspect monitoring and permitted inventories. Administrators also receive management controls; terminal-dependent actions require the host to enable browser terminals. Some notes controls are restricted to the designated operator. Missing buttons can therefore be expected. See Identity management. Browser account and API-key creation are host command-line operations, not buttons in this dashboard.

Check the target before acting: the local Host pane, an embedded peer Host pane, a prepared image row, an eight-digit container ID, and a saved snapshot represent different resources. A terminal on Host operates the server; a terminal on a container operates that instance. A peer's terminal operates that peer.

Panes appear automatically when relevant resources or image choices are present. The footer's pane preview control can reveal additional panes with Sample rows. Sample rows are examples with disabled actions; they are not deployed containers, snapshots, backups, or repositories. Available preview families also depend on access.

The screen examples gallery illustrates the dashboard and snapshot workflows using example data. Those pictures are illustrative and may predate the latest peer layout; the control descriptions here cover that layout.

Host monitoring and graph

Select a metric label to hide or show its series. This changes only the graph, not the server. Labels follow the selected time window; return to Live for the latest available readings.

Metric Meaning
CPU Host CPU utilization.
Memory Host memory use, with usage/capacity details.
Load Host load normalized to available processing capacity.
System Usage of the host's system filesystem.
Data Usage of the data filesystem. System and Data may refer to the same filesystem on some installations.
Containers Running customer instances plus snapshot previews against a 50-slot limit. The graph reaches 100% at 50.
VPNs Reported connected VPNs; the graph's count scale reaches 100% at 15. This scale is not a 15-connection admission limit.

The graph shows a five-minute window. Drag the history slider left to inspect older windows within the retained 30 minutes; select Live to return to now. Hover or focus the graph to inspect readings. Horizontal scrolling, including Shift plus the mouse wheel, moves through history. Resource readings are marked high at 75% and critical at 90%. Count bars have their own scales.

Each peer keeps independent live performance data. Its embedded pane shows an unlabeled performance graph filling the pane behind its host status and action buttons, with no metric labels, table-heading labels, or past-view slider. The small gray hardware and network information line is an outside footer below the peer pane. Open the full node view to use the labeled graph, metric visibility controls, and history slider. With the map background on, embedded peer panes share its translucent appearance. Turning the map off restores their normal pane fill. The hardware line reports available machine/CPU information and one Memory label followed by installed memory type, configured speed, and DIMM capacity. Missing hardware values are omitted. This installed capacity differs from the live used-memory value in the row.

Host buttons

The Host table columns are Host, Status, Version, IP, Peer, Uptime, Memory, Actions. Host-specific controls appear before Console Log, root terminal, and reboot on the right. A diagnostic expands below the row; selecting the same control again, or its Close button, closes it.

Control or icon What happens
Host name/cube, or non-button row area Opens Host Details for that host.
IP address — Geographic map Opens saved geographic locations. Hover over markers for system information; green means up, red down, yellow unknown.
Peer + — Connect another MYKOS host Opens the peer invitation dialog when no connection status is shown.
Peer status — View host IPsec status Opens reported host IPsec diagnostics.
Actions + — Add another peer Opens the local host's peer enrollment dialog when available.
Memory value — View host processes Opens the host process listing.
Red trash can — Stop and remove host VPN Opens the host VPN removal terminal workflow. Read its prompts to identify the selected site VPN. Peer unlink is a separate control.
Green document — Host Console Log Opens host log output.
Blue terminal — Host root terminal Opens an interactive root shell on the selected server; administrator access is required.
Red circular arrow — Reboot host Confirms the named host, then schedules its reboot. This interrupts all containers and connected users on that host.

Peer hosts

A peer is another MYKOS server paired for reciprocal administrator control over an IKEv2 VPN. Read the hostname and address before using any of its controls. A disconnected peer displays Offline and loses its actionable embedded pane. Connected peers also have a labeled background-map box. A dashed green line connects the local host to a peer when both have distinct saved coordinates. Peers without coordinates have a Connected box marked Location unavailable; no geographic position or line is invented. Boxes and lines disappear when the peer disconnects or its status becomes unavailable.

Peer control What happens
Small MYKOS flower — Open full node Opens that peer's full dashboard in another tab through the current host, including its OS, snapshot, and repository panes.
Red broken-chain icon — Disconnect peer After confirmation, revokes this peer relationship and removes its MYKOS peer VPN/shared controls. Reachable remote revocation is also requested.
+ — Add another peer on the named host Opens that host's own HTTPS dashboard for enrollment. Sign in there as its administrator; enrollment requires host-local approval.
Console Log, terminal, reboot, IP, Memory Operate on the named peer, with the same meanings as the Host controls above.

The compact peer action order is flower, unlink, plus, followed by any site VPN removal control and then the common log, terminal, and reboot controls.

To pair hosts, select the local Peer + or Add another peer, enter both reachable IPv4 addresses, and select Create invitation. Copy the private invitation into the other host's dialog and select Accept and connect within 15 minutes. Cancel dismisses the dialog without validating empty fields. Invitations grant reciprocal admin control and must stay private. Full prerequisites, certificate handling, and removal behavior are in Peer hosts.

Personal, pane, and shared customer notes are not forwarded through peers. Browser/API-key administration and further peer management also remain local.

OS panes and container rows

An image is a prepared OS and any startup state required to launch it. A container is a particular ID-specific instance with its own writable state, IP, and hostname. VM-backed guests also run within MYKOS-managed containers. A snapshot saves an instance at a point in time.

At the top of an OS pane, administrators can enter an eight-digit ID, choose an available OS image, and select the blue + (Start). This creates/starts an ID-specific instance from that image after confirmation. It does not install a missing OS image. Unavailable images cannot be selected. Use the row's green triangle to restart an existing stopped persistent container.

For eligible native starts with an existing backup, MYKOS separately asks whether to mount the original backup folders read/write. Accepting means changes inside the container can change those backup files.

Column or clickable value Meaning or action
ID Eight-digit instance/customer identifier. Select the row's non-button area to expand details; select again to collapse.
Leaf beside ID Shared customer notes for that ID; separate from pane notes.
Status Reported online/offline/unknown state.
Version Guest OS release, rather than host OS release.
IP Opens network/interface/gateway information and topology.
VPN Status/diagnostics or Add VPN, when supported for that guest. VM families without this control retain column alignment.
Uptime Time since the instance started.
Memory Used memory; select it for processes.
Actions Available console, terminal, lifecycle, snapshot, and VPN controls.

Expanded details include the image, OS, resources, addresses, and monitoring freshness. Unknown or stale data is not proof that a container stopped.

Container button reference

Icon / tooltip Action and effect
Green document — Console Log For native containers, opens log output.
Green document — HTTP graphical desktop For desktop guests, opens the interactive graphical console in another window/tab. Despite the document-shaped icon, this is not a read-only log. Requires admin access and a running guest.
Blue terminal — su - root Opens the instance's interactive root terminal for native Linux/Ubuntu.
Blue terminal — PowerShell commands Opens Windows/Windows Server command access.
Blue terminal — macOS shell Opens the macOS guest shell.
Green triangle — Start container Starts an existing stopped persistent instance using its saved disks.
Red square — Stop container Stops a persistent instance while retaining its disks. It does not save a new intentional snapshot.
Blue camera — Snapshot container Captures live state and leaves the instance running after completion; a brief capture pause may occur.
Red trash can — Delete container and saved data Requires typing the exact ID. Removes the container, its writable filesystem, MYKOS disks, and VPN settings. Images, intentional snapshots, rsync backups, and external/shared mounts are retained.
+ — Add VPN / Add another VPN Opens the interactive VPN setup workflow for an eligible running instance.
Red VPN trash can — Stop and remove VPN Opens the instance's VPN removal workflow. This is different from deleting the instance.

A saved native Linux memory snapshot currently requires its original container for restore. Keeping that snapshot does not make deleting its original container safe for a later restore. Legacy auto-remove containers must be converted to persistent storage before guarded start/stop/snapshot actions become available.

Images and base sessions

Image/build rows share OS panes with container rows. Their Status can show Queued, Installing, Preparing, Capturing, Failed, or Image. A prepared image displays its size and production time. A build still installing or capturing is not a ready image, even if its console is usable.

Image-row control What happens
Green document — Installation console Opens the selected installation's graphical console when provided.
Green document — Desktop console Opens the prepared desktop/base graphical console when provided.
Blue terminal — Edit base image / Connect to running base image Opens a generic base editing session. An idle base can be reopened on demand. This is not an ID-specific customer container.
Amber circular arrow — Reset base to captured image Requires typing the OS name. Discards uncaptured changes to that generic base and recreates it from the saved image/startup state. Close its console first.
Red trash can — Remove prepared image and generic base Requires the OS name. Removes the prepared image, generic base, and startup captures; dependent containers/snapshots block removal.
Red trash can — Delete failed image build and disks Requires the OS name. Deletes that failed build and its private disks.

Base edits must be captured before closing the editing session or logging out. A base-session disconnect queues a reset and discards uncaptured edits. To keep changes, leave the base session connected, open the host's sudo mykos text menu in a separate session, select f. Capture image, enter the OS, confirm, and wait for completion. Capture is a text-menu operation; there is no dashboard Capture button. Existing ID-specific instances keep their existing state.

Idle generic bases can stop after five minutes without an active session. A prepared image remains available for new instances even when its generic base is stopped. Do not confuse a stopped base with a missing image.

To build a missing image, use c. Build image in the host text menu and the correct OS identifier. See Image builds for supported native and VM types, media requirements, capture behavior, and recovery.

The small gray hardware line below the Host table includes measured internet Download and Upload speeds in Mbps when an official Ookla result is available. The collector measures twice daily, at midnight and noon Central, with the dev peer offset by 30 seconds. Hover over the line for the measurement time; failed or older results carry (stale). These measurements are separate from current network traffic shown on the graphs.

Snapshots

The Snapshots pane groups saved states by container. Choose the desired capture in its date/time selector before selecting an action. The displayed capture time and disk size follow that selection.

Icon / tooltip What happens
Blue circular arrow — Restore selected snapshot After confirmation, replaces the original container's current disks/live state and interrupts it. This is a rollback.
Red trash can — Delete selected snapshot After confirmation, permanently removes only the selected saved state; leaves the current container unchanged.
Green monitor — Preview selected snapshot Creates a separate temporary inspection session. The original instance and snapshot stay unchanged.

Desktop previews resume saved RAM and disks. Native Linux previews open the saved filesystem in an isolated shell; they do not resume captured RAM or services. Preview networking is blocked, changes are discarded on close, and sessions have a 30-minute maximum. Close preview explicitly ends the session. Previews consume capacity within the host's 50 running-instance/preview limit.

See Snapshot Preview for storage and isolation details.

VPN and network information

Select a container IP address to see its addresses, interface, networks, gateway, own VPN status, shared gateway, and default tunnel. Show connected guests expands or reduces the topology drawing. Solid green edges indicate a reported established SA; dashed gray edges are unconfirmed. Shared-network edges show membership, not a successful reachability test. A site SA alone does not prove full-tunnel internet connectivity.

Selecting an Up VPN status opens IPsec diagnostics. The setup/removal plus and trash controls open interactive workflows; follow their prompts and check the target before accepting. Native direct VPNs, shared gateways, host site VPNs, and MYKOS peer VPNs serve different purposes. See Networking. The geographic background represents saved locations, not a packet-path test.

rsync backup accounts

The rsync pane lists backup account ID, application type, OS, used disk, last modification, and subscriber state. These are backup SSH accounts, not browser login accounts. The inline creation controls take an eight-digit ID and the client SSH public key, then Create account.

Control What happens
Change key Opens the account public-key editor. Save replaces its authorized public key; Cancel dismisses the form.
View / get keys Retrieves keys stored in the client's backup. The dialog may include a private key; Download keys saves a local copy. Treat it as secret.
Remove backup account First requires the exact ID. A second prompt asks whether to delete all backup data: OK deletes the data; Cancel retains the data but still removes account access. Canceling the first ID prompt aborts removal.
Close in Backup keys Dismisses the key display.

Account creation does not prove that a fresh rsync backup has run. Consult the last-modified and storage values, then verify the intended backup separately.

Repositories

The Repos pane shows repository name, disk use, last modification, and latest RPM. Select a repository name to browse its published directory in another tab. A configured remote source can make this pane read-only, with management buttons hidden; its Server label identifies the source.

Control What happens
Up arrow — Enable repositories Confirms, then starts Apache.
Down arrow — Disable repositories Confirms, then stops Apache. This can also disconnect the dashboard and other Apache sites; recovery may require the host CLI.
Circular arrows — Sync repositories Confirms and queues the background repository sync workflow. It may install dependencies and use substantial disk/network capacity. Disabled while sync is active.
Row trash can — Delete Requires typing the repository name, then permanently deletes that repository and its content.

The status line reports storage, Apache state, sync state, and collection time. Enabling Apache is different from starting a repository sync.

Notes

Several small icons resemble one another. Their location and tooltip identify the kind of notes they open; a document in an Actions row can instead be a log or graphical console.

Control Scope
White document near a pane heading — Host notes, Windows notes, etc. Private operator requests/reference for that pane.
Orange document in local Host — Personal notes Personal notes private to the designated operator.
Leaf beside a container ID — Shared notes for that ID Customer/ID notes, separate from the operator work list.
Terminal title-bar notes button, where present Notes associated with the terminal pane.

Save writes the edited text. Reload retrieves the server version and asks before discarding unsaved edits. Close dismisses the dialog and asks before discarding unsaved text. Saving checks the revision so a concurrent edit is not silently overwritten. If a conflict occurs, keep a private copy of your pending text before reloading, then reconcile and save again.

On this installation, the authorized hourly maintenance workflow uses personal and dashboard pane notes as requests. Saving a note does not itself execute a change. Shared customer notes and the documentation's historical operator notes are separate from that work list. Notes remain host-local and are excluded from peer forwarding and public documentation/release content.

Common workflows

Inspect an instance

  1. Use the header's OS link to reach its pane.
  2. Select the ID row to inspect details; select IP for topology or Memory for processes.
  3. Open Console Log for native logs, or HTTP graphical desktop for an interactive desktop.
  4. Use the terminal only when you intend to issue commands to that instance.

Start a new instance or restart an existing one

  1. For a new instance, enter an unused eight-digit ID and select a prepared image.
  2. Select the pane's blue + (Start); read any backup-mount prompt, then confirm.
  3. Wait for the queued/running operation to finish and inspect the resulting row.
  4. For an existing stopped persistent instance, use its green Start container triangle instead.

Save and inspect a point in time

  1. On a running persistent instance, select the camera and confirm.
  2. Wait for snapshot completion; find the ID in Snapshots and select its capture time.
  3. Use the green monitor for a separate preview, then Close preview when finished.
  4. Use Restore only when you intend to replace the original instance's current state.

Operate another MYKOS host

  1. Locate its compact Host pane and verify the hostname/IP.
  2. Use its Host controls for host diagnostics or terminal access.
  3. Select its small flower to open the full node for that host's guests and snapshots.
  4. Recheck the target name before lifecycle or destructive actions.

Messages and troubleshooting

Symptom What to check or do
A pane or button is missing Check role, available images, automatic pane visibility, and whether the pane is a peer view. Sample preview does not grant privileges.
A button is gray Check running/stopped state, an operation in progress, persistence support, image reset/removal state, or capacity. Read its tooltip.
“Image storage is busy” / last successful inventory The UI retains a previous inventory during slow storage reads. Wait for fresh data before assuming an image disappeared.
Unknown, stale, or unavailable monitoring Inspect collection time and connection errors. Avoid interpreting an old value as current state.
Container limit reached There are 50 running customer instances/previews. Close an unneeded preview or deliberately stop an instance before starting another.
A console/preview does not open Allow popups for the MYKOS origin, check admin/terminal permissions and guest state, and retry only after checking the original operation's status.
Request returned an error while starting/snapshotting The action may already be queued. Inspect the row/job status before submitting it again. A failed status read is not proof the action failed.
Peer Offline / Status unavailable Verify the peer host, VPN, HTTPS reachability, and certificate. Do not redirect commands to the local host as a substitute.
Base reset/removal failed Read the image-row error and dependencies. Resolve it before retrying; do not delete dependent customer instances as a diagnostic step.
You need to change a browser password or API key Use the host identity tools described in Identity management; backup key buttons affect a separate identity system.

For deeper procedures, use Images, Desktops and snapshots, Networking, Peers, and Installation/recovery.

Pane status summaries appear beside their pane labels after a middle dot, including live counts, refresh times and errors. They remain gray and update in place; the ID/start controls and table begin below the heading without a separate status row.

Receiver appearance

Choose Receiver in the footer Theme selector (also available on the login screen). The leaf cycles Dark → Light → Receiver. The browser remembers the selection. Receiver uses a brushed aluminum face, compact blue-lit black VU meters, round metal action buttons and a radio-style recall band with a one-minute tuning knob. The larger flower has a transparent background.

The four VU meters show actual CPU, memory, System and Data percentages from the existing host collector, following the same selected history and freshness rules as the graph. Missing or stale readings show a dim face and a dash; needles stop at 100% while the value still reports overload. The original history graph, metric controls and all actions remain available. Compact peers inherit the appearance without adding meter height. This is an appearance option, not an audio interface or a change to host resource policy.

Receiver control bank

Receiver now uses the approved continuous faceplate layout. Click Illumination to add 10 percentage points to the blue meter lighting, cycling from 100% back to 0%. Only the marker line moves; the knob body stays fixed. The percentage readout updates too, and the browser remembers the setting. Enter/Space also operate the knob. Slow / Normal / Fast changes needle damping. Display turns the receiver meter lighting/needle display off and on; it does not control server power or stop collection. The history band retains dragging and keyboard control, and Live resets the selection. History graph reveals the detailed graph and metric controls. Dark/Light restore the original layout and original control nodes.

The black tuner shows host information with fixed light-blue container and green VPN signal indicators. They share recorded chart data and the selected history endpoint. Counts are scaled to50 containers and15 VPNs; stale counts show a dash and unlit bars. They update at most once per second without additional collector/API polling.

Receiver instruments and OS selector

The smaller black VU faces sit inside the black performance window, with white needles/scales and blue light shining upward from the bottom. The hostname sits outside that window immediately above the recall controls, in royal blue. Fixed graduated container/VPN indicators use light blue/green. Keyboard focus on knobs has a light-blue cue; pointer interaction has no red/orange focus ring.

Click the Source knob to advance to the next available OS pane, cycling back through All OS panes. Each click moves only the marker line and updates the OS label; the knob body stays fixed. The adjacent dropdown provides the same choices for direct selection; the knob supports Enter/Space as a normal button. Only enabled, available panes appear. The selector preserves each pane’s configured visibility and permissions and automatically falls back to All if the selected pane becomes unavailable. Section links select their corresponding available OS pane. Other themes restore the original pane visibility.

Receiver performance enclosure

The taller black performance enclosure groups the VU faces, fixed signal count bars, Display switch, radio recall/Live control, needle-response switches, Illumination knob and OS Source dial/dropdown. The hostname remains outside above the enclosure. Control labels stay light against the dark background, while knobs/buttons retain their metal finish. Lit container signal bars use45% opacity and VPN bars85%; inactive segments stay dim. Other themes retain their existing appearance. The original history controls and OS visibility rules remain intact.

Receiver radio controls

The black instrument panel shows two fixed, ascending signal-style bars to the left of the four VU meters: running containers (full scale50) and VPN links (full scale15). Exact counts remain visible; missing/stale readings show a dash with no lit bars. These indicators follow the selected history endpoint rather than scrolling through observations.

Illumination is centered to the right of the meters. Each click adds10 percentage points, with100 wrapping to0. The blue lamp gradient has twice its former gain across the knob range; the meter glass brightness reaches2× at100%. Display Off remains a separate visual-only control.

The radio-style recall band has a vertical tick every15seconds, longer minute marks and labels in minutes back. Its knob on the right steps one minute earlier per click, through25minutes before wrapping to live. The band can still be dragged or adjusted with the keyboard; Live resets it. Slow, Normal, Fast and Live are small round brushed-metal buttons. Source still cycles available OS panes and keeps the displayed label synchronized. Other themes retain their original history controls.
