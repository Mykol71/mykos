Historical Linux integration checklist

This is a source/staging validation, not a claim that a production deployment ran. Before activation, validate on an approved compatible Linux staging host:

  1. Package availability, selected Python/venv, ownership, and systemd-analyze verify.
  2. HTTPS proxy prefix, Origin, cookies, WebSocket routing, TLS, and SELinux permissions.
  3. Collector freshness, rootful Podman discovery, snapshot ownership/readability, duplicate-shop handling, and actual image OS metadata.
  4. Both socket-activated helper services, bounded live diagnostics, and authorization denials for nonadmins/read keys.
  5. Prepared RTI image, correct NIC/DHCP behavior, IPsec configuration and reachability, an approved staging job with and without read/write backup mounts, and stop behavior.
  6. Terminal opt-in, PTY behavior, disconnect cleanup, and session restrictions.
  7. Code rollback and identity-data recovery on a disposable host, including service account numeric ownership and independent dependency/image/data backups.

The historical helper source was absent. Supplied helpers are compatible replacements based on the app's protocol and existing POS commands; their integration behavior must be tested. The global installer does not fabricate RTI software, backups, images, subscription entitlements, networks, Meraki configuration, TLS certificates, or in-container Checkit. Legacy billing/TSR/blacklist jobs remain manual and unscheduled.
